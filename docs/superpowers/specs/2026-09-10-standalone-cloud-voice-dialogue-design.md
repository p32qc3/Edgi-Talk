# Edgi-Talk 脱离电脑云端语音对话设计

## 目标

在现有 AB1 宠物工程上增加“一问一答”的中文语音对话。设备完成一次配置和烧录后，只需供电和 Wi-Fi，不依赖电脑运行。用户点击屏幕麦克风按钮说话，设备将录音经 ECS 转发给阿里云百炼千问，随后播放语音回答，并可执行经过批准的宠物动作。

第一版以课堂演示稳定性和板端低负担为优先，不实现电话式全双工对话、唤醒词和边说边播。

## 已确认约束

- 使用现有 Edgi-Talk 的 M33 与 M55，不新增主控。
- 使用阿里云 ECS `47.116.168.34` 作为中转服务。
- 使用百炼 `qwen-audio-3.0-realtime-flash`，API Key 只保存在 ECS。
- 当前没有域名和 HTTPS 证书，第一版使用 HTTP 加设备专用密码，仅用于课程演示。
- 点击麦克风开始录音；连续静音约 1.5 秒自动结束，再次点击可手动结束。
- 单次说话最长 8 秒，超过后自动结束，防止内存、网络和费用失控。
- AI 故障不能阻塞宠物界面、原有游戏或 51 通信。

## 方案选择

采用“板端录完一句再上传，ECS 调用云模型，板端再播放回答”的半双工方案。

未采用以下方案：

- 板端到云端保持实时双向连接：延迟较低，但回声、断线恢复、TLS 和内存管理复杂，超出第一版需要。
- 语音识别、文本模型、语音合成三个服务分开调用：控制更细，但接口和故障点更多。

## 系统边界

### M33：音频端

- 继续使用现有 16 kHz、16 位、单声道 PDM 麦克风采集。
- 接收 M55 的开始、停止录音命令。
- 每 20 ms 提供一帧 PCM，并计算音量供静音判断使用。
- 接收 ECS 返回的 PCM 音频并通过现有扬声器通路播放。
- 录音与播放互斥，避免扬声器声音被麦克风再次录入。

### M55：交互与联网端

- 将现有屏幕麦克风按钮连接到语音状态机。
- 负责 Wi-Fi 连接、录音分段收集、HTTP 上传、结果解析和回答音频下载。
- 更新界面状态，但所有网络工作都在后台任务运行，不阻塞触摸和动画。
- 将服务器返回的动作交给现有宠物接口；51 未连接时不影响普通对话。

### ECS：密钥与云模型端

- 对设备进行身份校验、限制请求频率和录音大小。
- 从服务器环境变量读取百炼 API Key，连接千问语音模型。
- 保存短时回答音频，并向设备返回文字、动作和音频编号。
- 不永久保存用户录音；完成请求或超时后删除临时文件。
- 使用独立服务账户运行，异常后自动重启。

## 板上数据交换

M33 与 M55 使用两个有界的共享环形缓冲区：一个传录音，一个传回答音频。缓冲区地址必须由双方链接配置共同预留，并在编译映射文件中确认不与现有共享状态、堆栈、界面内存或外部 Flash 存档重叠；不直接使用未经验证的固定地址。

每个音频块带序号、有效长度和状态标记。写入方只有在缓冲区有空间时写入，读取方消费后释放。缓冲区满时结束本轮并报告错误，不覆盖未读数据。

## 一轮对话的数据流

1. 空闲时界面显示“点击说话”。
2. 用户点击麦克风，M55 生成唯一 `turn_id`，通知 M33 开始录音，显示“正在听”。
3. M33 按 20 ms 输出 PCM；M55 分段收集。检测到约 1.5 秒连续静音、用户再次点击或达到 8 秒时停止。
4. 录音过短或只有静音时不访问云端，界面提示“没有听清，请重试”。
5. M55 将本轮 16 kHz、16 位、单声道 PCM 上传到 ECS，显示“思考中”。同一轮重试继续使用相同 `turn_id`。
6. ECS 校验设备与大小，把音频送入千问，得到识别文字和回答音频。
7. ECS 根据识别文字生成一个白名单动作，返回 `turn_id`、识别文字、回答文字、动作和短时音频地址。
8. M55 校验 `turn_id` 和动作，下载回答音频并分段送给 M33，显示“正在回答”。
9. M33 播放语音。M55 对每个 `turn_id` 最多执行一次动作，播放完成后回到“点击说话”。

## ECS 接口

### `POST /v1/voice/turn`

- 请求头包含设备编号、设备专用密码、`turn_id`、采样率和录音长度。
- 请求体为原始 PCM，最大 256000 字节，即 8 秒录音。
- 返回小型 JSON：本轮编号、识别文字、回答文字、动作、音频编号和过期时间。
- 相同设备和 `turn_id` 的重试返回同一结果，不重复调用模型。

### `GET /v1/voice/audio/{audio_id}`

- 返回 16 kHz、16 位、单声道 PCM，M55 边下载边交给 M33 播放。
- 音频只允许创建它的设备访问，短时间后自动失效。
- 回答语音限制在 12 秒内；超出时保留屏幕文字并播放简短提示。

接口错误统一返回简短错误码，板端不解析服务器内部错误文本。

## AI 动作边界

第一版只允许以下动作：

- `none`：普通聊天，不改变宠物。
- `show_status`：打开宠物状态。
- `start_simon`：请求开始记忆灯游戏，并沿用现有 51 可靠通信流程。
- `feed`：调用现有喂食操作。
- `home`：返回宠物主页。

ECS 只从识别文字中判断这些明确意图；M55 再做一次白名单校验。未知、缺失或格式错误的动作一律当作 `none`，云端不能直接指定引脚、内存地址或任意函数。

## 界面行为

- 空闲：`点击说话`
- 录音：`正在听…`，再次点击可停止
- 上传和云端处理：`思考中…`
- 播放：`正在回答…`
- Wi-Fi 未连接：`网络未连接`
- 超时或服务器失败：`网络异常，请重试`
- 纯静音：`没有听清，请重试`

用户可以在录音阶段取消本轮。处理和播放阶段不接受新的录音，防止两轮音频混合。返回按钮仍可用，但只取消界面等待，不执行尚未确认的动作。

## 配置与安全

- 百炼 API Key 仅放在 ECS 的受限环境配置中，不写入源码、固件、日志或 GitHub。
- 设备专用密码与服务器地址放在本地私有配置文件；仓库只提交不含真实值的示例文件。
- Wi-Fi 账号使用现有持久化配置，首次配置后断电重启可自动连接。
- ECS 只开放必要的 SSH 和 HTTP 端口，对语音接口做限速、长度检查和失败次数限制。
- 日志只记录本轮编号、耗时和错误码，不记录 API Key、设备密码或完整录音。
- HTTP 无法防止同一网络上的窃听。第一版仅用于课程演示；绑定域名后把设备到 ECS 升级为 HTTPS，不改变业务接口。

## 故障处理

- Wi-Fi 断开：本轮立即失败，后台自动重连，宠物界面继续运行。
- 上传中断：相同 `turn_id` 最多重试一次，避免长时间卡住。
- 云端超时：整轮最长等待 25 秒，超时后回到空闲。
- 重复返回：按 `turn_id` 去重，动作只执行一次。
- 回答音频下载失败：仍显示回答文字，不执行第二次云端请求。
- M33/M55 音频缓冲区异常：停止本轮并复位音频状态，不重启整个设备。
- 51 离线：可以聊天和查看状态；启动记忆灯时显示 51 未连接，不伪造成功结果。

## 实施范围

第一版包含：

- M33 录音控制、音频共享和回答播放。
- M55 麦克风按钮、对话状态机、Wi-Fi/HTTP 客户端、动作桥接和状态提示。
- ECS 语音中转服务、密钥管理、请求去重、限速和自动启动。
- 示例配置、部署说明、自动测试和双核固件构建。

第一版不包含：

- 唤醒词、连续监听、全双工打断和回声消除。
- 用户账号、长期聊天记录、远程固件升级。
- HTTPS 证书自动申请。
- 新增超出白名单的硬件控制能力。

## 验收标准

### 自动检查

- M33/M55 音频块序号、满缓冲区和复位路径测试通过。
- 静音结束、8 秒上限、按钮停止和空录音测试通过。
- M55 对状态迁移、超时、重试、重复结果和动作白名单测试通过。
- ECS 在模拟千问响应下完成鉴权、大小限制、幂等、音频过期和错误返回测试。
- M33、M55 全量编译通过，映射文件确认共享内存无重叠。

### 实机检查

- 严格按“先 M33、后 M55”的顺序烧录并校验。
- 板子只连接普通电源、不连接电脑时，可自动加入 Wi-Fi。
- 点击麦克风说中文后，屏幕依次显示录音、思考和回答状态，并从扬声器播放回答。
- “查看状态”和“开始记忆灯”能触发现有宠物功能；同一请求不会执行两次。
- 断网、ECS 停止、千问超时、51 拔线时，界面均能恢复，原有宠物功能不会卡死。
- API Key 和真实设备密码不出现在 Git 历史、固件串口日志和公开仓库中。

## 烧录与回退

- 保留当前已验证的 AB1 固件作为回退版本。
- 新版本仍先构建和烧录 M33，再构建和烧录 M55。
- 任一核心启动失败时，重新烧录已验证 AB1 固件即可恢复离线 AI、宠物界面和 51 通信功能。
